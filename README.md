# 异人之下小程序 · 自动点赞（Windows 原生，零依赖）

对应任务：「热心异人」阶段任务第一项「送出点赞 500/2000/5000」。
实现方式：抓小程序窗口画面 → 形状匹配找**灰色空心 ♡** → 点击 → 回读像素确认变红 → 滚屏继续。
不抓包、不改包、不碰任何接口，只有鼠标点击。

## 风险（先看）

- 官方公告原话：「现有黑产工作室在试图批量刷小程序等级，目前异常……」——本轮就在抓脚本刷量。刷多了可能限流、取消领奖资格、封社区号。
- 500/2000/5000 这种量级人手点不出来，行为特征很明显。建议一次几十个，别挂通宵。
- 第二、三项（有效评论、点赞>10 的评论）脚本做不了，得自己发真实内容。

## 环境

Windows + PowerShell 5.1（系统自带），**不需要 pip / Python / OpenCV**。脚本已存成 UTF-8 BOM，中文不会乱码。

必须用**正常完整性**的 PowerShell 运行：DSH 沙箱把进程降权到 Low 时，Windows 的 UIPI 会静默丢弃注入的鼠标事件（表现为：能截图能识别，点了没反应）。桌面双击 bat / 普通 PowerShell 窗口都没问题。

## 用法

1. PC 微信里打开小程序，点小程序右上角 `…` → 在新窗口中打开，让它是一个独立窗口。
2. 把窗口拖到屏幕内、放在最前面，别被浏览器压住。
3. 停在有 ♡ 的列表页（异人站广场，或搜索「升级」出来的帖子列表）。
4. 先识别测试（不点击）：
   ```powershell
   .\run.bat -DebugScan
   ```
   每个识别到的心都会打印「窗口坐标 / 屏幕坐标 / 尺寸 / 尺度 / 是否已点红」。
5. 正式跑（默认 500 个，可以自己改）：
   ```powershell
   .\run.bat -Target 50
   ```

## 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `-Target` | 500 | 目标点赞数（**0 = 一直点，不设上限**） |
| `-MaxClicks` | 0（不限） | 最多点击次数保险 |
| `-MaxRuntimeMin` | 0（不限） | 最长运行分钟数，到点自动收尾 |
| `-WindowTitle` | 异人 | 小程序窗口标题关键字 |
| `-Fraction` | 0.90 | 心形笔画命中比例（越大越严） |
| `-Tolerance` | 12 | 笔画亮度容差（越小越严） |
| `-DryRun` | - | 只识别不点击 |
| `-DebugScan` | - | 列出所有匹配及其红/灰状态后退出 |
| `-SaveShots` | - | 每次成功点赞后存一张现场截图到 captures/ |
| `-FromImage xx.png` | - | 用已保存截图离线调试识别 |
| `-MinDelayMs/-MaxDelayMs` | 1000/2400 | 两次点赞的随机间隔 |

## 不会自己停（v3）

以前会「自己停」，触发点是这几个，现在全部改成自救而不是退出：

| 以前会停的情况 | 现在的行为 |
|---|---|
| 连续 8 屏没得点（列表刷到底/全是红心） | 滚回列表顶部重新扫；每 3 次自救等 40 秒让新帖刷出来；不再退出 |
| 累计 8 次点击没反应（某颗心点不动） | 先自动点「返回」退回信息流；不行就清空黑名单、滚一屏、继续点，不再退出 |
| 误点进帖子详情/评论页（那是评论的赞，点不出红心） | 连点 3 次没反应 → 用 `templates/back_arrow.png` 找到返回箭头自动退回信息流 |
| 小程序窗口被关掉/换标题 | 自动重新查找窗口；找不到就每 5 秒重试，最多等 5 分钟 |
| 窗口被拖动导致尺寸异常 / 抓屏报错 | 这一轮跳过，1 秒后继续 |
| 识别环节抛异常 | 打印错误后继续，不中断 |
| 点击次数到上限 | 默认改成 0 = 不限，只有 `-Target` 或 `-MaxRuntimeMin` 才会收尾 |

> 老版本有个真 bug：`totalMiss` 只在失败时累加、成功后从不清零，所以整场跑下来累计 8 次失败必停——这就是「老是自动停止」的主要来源。现在成功、自救都会清零。

要停下来只有三种方式：达到 `-Target`、到达 `-MaxRuntimeMin`、你按 Ctrl+C 或关窗口。

如果日志反复出现「连续自救多次」，通常说明当前页既不是信息流也没有返回箭头（比如百科页/弹窗），脚本会一直等——手动按一下返回就恢复了。

## 识别是怎么做的（v2）

- **多尺度模板**：0.78 / 0.88 / 1.0 / 1.14 四个尺寸。列表页的心约 22px，话题详情页只有 17px，单一尺度会漏掉一大半——这是「一页能点4个却只点1个」的主因。
- **亮度形状匹配**：只判断「笔画像不像心形 + 周围是不是白底」，不看具体 RGB，所以悬停高亮、抗锯齿、深浅灰都能容忍。
- **1px 相位容差**：同一个图标滚动后会差半个像素，笔画允许落在相邻格，不会再偶发漏识别。
- **红心自动跳过**：点过的变红就不点第二次。
- **一页点完才滚**：识别到心但都点过了才滚屏；一个都没识别到（可能刚点赞有 toast/动画）会先重试 4 次再滚，不会一页只点一个就跳走。
- **点不动会补一下**：点完 1.2 秒没变红，在同一点再补一次；还没反应才记入黑名单跳过。
- **遮挡守卫**：点之前用 WindowFromPoint 确认这个坐标真属于小程序窗口，被挡住就换一颗心，全被挡就自动把窗口提到最前。
- **窗口拖拽保护**：窗口被拖动/缩放时尺寸可能瞬间非法，脚本会跳过这一轮继续，不会崩。

## 文件

- `auto_like.ps1` —— 主程序（PowerShell + 内嵌 C#）
- `run.bat` —— 带参数运行
- `1-先测试-3个.bat` / `2-正式运行-500个.bat` / `3-一直跑到手动停.bat` —— 双击即用
- `templates/like_heart.png` —— 点赞按钮模板（22x18）
- `templates/back_arrow.png` —— 返回箭头模板（18x28，误进详情页时自动退回用）
- `captures/` —— 调试截图（失败/成功现场）
- `使用说明.txt` —— 简版说明

## 实测

- 离线校验：三张不同页面的现场截图，灰色心全部识别（2/2、2/2、2/2），红心正确跳过，无假阳性。
- 在线：`-Target 3` 3/3、`-Target 8` 8/8 全部点赞成功（每次回读像素确认变红）。
- v3 在线回归：`-Target 3` 3/3，期间笔记窗口被拖动两次（位置变化日志可见）也没中断，结束信息带自救次数与用时。

## 故障排查

1. 先 `-DebugScan`：识别数为 0 → 页面不对/全红心/窗口被遮挡；有识别但点了没反应 → 检查是否低完整性环境。
2. 窗口别拖到屏幕外，会提示「窗口有一部分在屏幕外」。
3. 不要一边拖窗口一边跑。
4. 想换模板：截一张灰色空心 ♡（1:1 原始尺寸）覆盖 `templates/like_heart.png`。
